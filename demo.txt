# Load Generator Complete Usage Guide

## 📦 Setup & Installation

### Step 1: Create the Load Generator Directory

```bash
# Navigate to your project
cd trading-system

# Create loadgen directory
mkdir -p loadgen

# Create the main file
touch loadgen/main.go

# Copy the load generator code into loadgen/main.go
```

### Step 2: Initialize Go Module (if not already done)

```bash
cd loadgen

# Initialize go module
go mod init loadgen

# Get WebSocket dependency
go get github.com/gorilla/websocket
```

### Step 3: Build the Load Generator

```bash
# Build the binary
go build -o loadgen main.go

# Make it executable
chmod +x loadgen

# Verify it works
./loadgen --help
```

---

## 🚀 Running the Load Generator

### Basic Command Structure

```bash
./loadgen -url <server_url> -clients <number> -duration <seconds> -workload <type>
```

### Arguments Explained

| Argument | Description | Default | Example |
|----------|-------------|---------|---------|
| `-url` | Server URL to test | `http://localhost:8080` | `http://192.168.1.100:8080` |
| `-clients` | Number of concurrent clients | `10` | `50` |
| `-duration` | Test duration in seconds | `60` | `300` (5 minutes) |
| `-workload` | Type of workload to run | `cpu-bound` | See below |

### Workload Types

| Workload | Description | Use Case |
|----------|-------------|----------|
| `cpu-bound` | Query same 10 stocks (cache hits) | Test CPU limits |
| `io-bound` | Query unique stocks (cache misses) | Test disk I/O limits |
| `mixed` | 50% hot, 50% cold stocks | Test balanced load |
| `write-heavy` | Place buy/sell orders | Test matching engine |
| `portfolio` | Query user portfolios | Test complex queries |
| `orderbook` | Query order books | Test matching engine reads |
| `websocket` | Connect WebSocket clients | Test real-time updates |

---

## 📊 Workload Examples

### 1. CPU-Bound Workload (High Cache Hit Rate)

**What it does**: Queries the same 10 popular stocks repeatedly  
**Expected result**: 99% cache hit rate, ~28,000 requests/sec

```bash
# Quick test (1 minute, 10 clients)
./loadgen -url http://localhost:8080 -clients 10 -duration 60 -workload cpu-bound

# Full test (5 minutes, 50 clients)
./loadgen -url http://localhost:8080 -clients 50 -duration 300 -workload cpu-bound
```

**What to observe**:
- Cache hit rate should be ~99%
- CPU utilization should be high (80-100%)
- Disk utilization should be low (5-10%)
- Throughput should be high (~20,000-30,000 req/s)

---

### 2. I/O-Bound Workload (Low Cache Hit Rate)

**What it does**: Queries unique stocks every time (never repeats)  
**Expected result**: ~0% cache hit rate, ~1,500 requests/sec

```bash
# Quick test (1 minute, 10 clients)
./loadgen -url http://localhost:8080 -clients 10 -duration 60 -workload io-bound

# Full test (5 minutes, 50 clients)
./loadgen -url http://localhost:8080 -clients 50 -duration 300 -workload io-bound
```

**What to observe**:
- Cache hit rate should be ~0-2%
- CPU utilization should be low (20-30%)
- Disk utilization should be high (80-100%)
- Throughput should be lower (~1,000-2,000 req/s)

---

### 3. Mixed Workload (Balanced)

**What it does**: 50% popular stocks (cache hits), 50% unique stocks (cache misses)  
**Expected result**: ~50% cache hit rate, ~8,000 requests/sec

```bash
# Run mixed workload
./loadgen -url http://localhost:8080 -clients 50 -duration 300 -workload mixed
```

**What to observe**:
- Cache hit rate should be ~50%
- Both CPU and disk should show moderate utilization (50-60%)
- Throughput should be between CPU and I/O bound values

---

### 4. Write-Heavy Workload (Order Placement)

**What it does**: Continuously places buy/sell orders  
**Expected result**: Tests matching engine and database writes

```bash
# Run order placement test
./loadgen -url http://localhost:8080 -clients 10 -duration 60 -workload write-heavy
```

**What to observe**:
- Lower throughput (~500-800 req/s) due to transactions
- Some requests may fail (insufficient funds) - this is expected
- Database writes will be high
- Tests the matching engine performance

**Note**: Make sure you have test users with sufficient balance!

---

### 5. Portfolio Workload

**What it does**: Queries user portfolios (complex database joins)  
**Expected result**: Tests complex query performance

```bash
# Run portfolio query test
./loadgen -url http://localhost:8080 -clients 20 -duration 60 -workload portfolio
```

**What to observe**:
- Moderate throughput (~3,000-5,000 req/s)
- Database CPU usage will be higher (complex queries)

---

### 6. Order Book Workload

**What it does**: Queries order books for different stocks  
**Expected result**: Tests matching engine read performance

```bash
# Run order book query test
./loadgen -url http://localhost:8080 -clients 20 -duration 60 -workload orderbook
```

**What to observe**:
- Measures order book retrieval speed
- Tests in-memory matching engine performance

---

### 7. WebSocket Workload

**What it does**: Opens WebSocket connections and receives trade updates  
**Expected result**: Tests real-time broadcasting capability

```bash
# Connect 100 WebSocket clients
./loadgen -url http://localhost:8080 -clients 100 -duration 60 -workload websocket
```

**What to observe**:
- Number of successful connections
- Messages received (need to place orders in another terminal to generate trades)
- Message throughput

**Tip**: Run this alongside the write-heavy workload in another terminal:
```bash
# Terminal 1: WebSocket listeners
./loadgen -url http://localhost:8080 -clients 100 -duration 120 -workload websocket

# Terminal 2: Generate trades
./loadgen -url http://localhost:8080 -clients 5 -duration 120 -workload write-heavy
```
